## 0. 인터뷰에서 확정된 결정사항

| 항목 | 결정 |
|------|------|
| 디스플레이 | 테두리 없는 창(Borderless) 기준. Electron 오버레이 유지. 1920×1080 기준 설계 |
| 최적배치 적용 | **제안만 표시, 수동 배치** (게임 조작 개입 없음) |
| 제안 표시 | 별도 미니 그리드. **아이콘 + 셀별 최종 강화수만** 표시 (간결). 석판 회전은 아이콘 회전으로 표현 |
| 계산 트리거 | **수동** (버튼/단축키). 계산 중 로딩 표시 + **직전 완료본 유지 표시**, 완료 시 갱신 (전투 중 돌려놓고 나중에 확인하는 흐름) |
| 우선순위 입력 | 콤보 순위 리스트(드래그) + 강화 배분 모드 토글 (콤보템 최대강화 / 균등 강화) |
| 석판 제약 | 게임 규칙 준수: 배치 불가 위치, 회전 불가 석판, 석판/아티팩트 발동조건 |
| 빌드 비교 | **그때그때 브라우징** (자동 비교 없음). 표시 내용: 재능/기적/무기/과일꼬치/콤보 + 작성자 설명 + 아티팩트 섹션 |
| 팀원 패널 | 후순위. **F1 토글**. 게임이 팀원 인벤토리를 동기화해줌 → 팀원 플러그인 설치 불필요 (검증 필요) |
| V키 인벤토리 위치 | 화면 **중앙** → 오버레이 패널은 좌우 가장자리 배치 |
| 개발 프로세스 | 각 기능 개발 전 HTML 시안 승인 (위치·편의성 위주) |

## 1. 공통 아키텍처

```
게임 (BepInEx 플러그인)  ←WS 5827→  Electron 오버레이
                                      ├─ renderer: 패널 UI
                                      └─ main: 전역 단축키, wiki API fetch(CORS 회피)+캐시
```

- 패널은 모두 드래그 이동 가능, 위치는 로컬에 저장/복원.
- 단축키 (전역):

| 키 | 기능 | 비고 |
|----|------|------|
| `Ctrl+D` | 최적 배치 패널 토글 | 기존 퀵카드를 이 패널로 대체 |
| `Ctrl+R` | 최적 배치 계산 실행 | 패널 내 버튼과 동일 |
| `Ctrl+B` | 위키 빌드 패널 토글 | 신규 |
| `F1` | 팀원 패널 토글 | 신규 (기존 T안은 입력 충돌로 변경) |
| `Shift+Tab` | 풀 오버레이 | 기존 유지 |
| `Ctrl+Shift+M` | 미니맵 HUD | 기존 유지 |
| `Esc` | 활성 패널 닫기 | 기존 유지 |

## 2. 기능 ① 최적 배치 (M1)

### UX
1. `Ctrl+D` → 좌측 패널. 상단: 상태 배지(`✓ n분 전 계산 완료` / `계산 중… n%`) + `▶ 다시 계산` 버튼.
2. 계산 중에도 **직전 결과 그리드는 그대로 표시** ("이전 결과 표시 중" 안내). 완료 시 자동 교체.
3. 미니 그리드(실제 인벤 크기 동일, 기본 6×5): 각 셀에 아이콘, 우하단에 최종 강화수(노란 숫자). 석판은 강화수 없음, 아이콘을 회전 방향대로 렌더.
4. 하단: 콤보 우선순위 드래그 리스트(추가/삭제) + 강화 배분 모드 토글.

### 계산 파이프라인
- 오버레이 → WS `optimize.request` (우선순위, 모드) → 플러그인이 **메인 스레드에서 인벤 스냅샷** → 백그라운드 스레드에서 탐색(SA) → `optimize.progress` (n%) → `optimize.result` (배치+셀별 최종강화수+타임스탬프).
- 결과는 플러그인/오버레이 양쪽에 캐시 → 패널 재오픈 시 마지막 결과 즉시 표시.

### 기존 엔진(CustomArrangementOptimizer.cs) 대비 필요한 개선
| # | 현재 | 필요 |
|---|------|------|
| 1 | 모든 석판 90° 회전 허용 (`allowTabletRotation` 전역 플래그) | **석판별 회전 가능 여부**를 게임 데이터에서 읽어 반영 |
| 2 | 석판 보너스 = 인접 4칸 +1 하드코딩 | **석판별 실제 보너스 패턴/수치 매트릭스** 사용 (게임 데이터 추출 — 조사 태스크) |
| 3 | 점수 = `flameGround`/`darkCloud` 하드코딩 가중치 | **콤보 시스템 기반 점수 함수**: 우선순위 리스트 → 순위별 가중치, 콤보 소속 아티팩트의 강화수 반영 |
| 4 | 배치 불가 칸 개념 없음 | 석판 배치 불가 위치 제약 반영 |
| 5 | 발동조건 5종(위/아래/내부/테두리/양끝)만 | 게임 내 전체 criteria 커버리지 확인·보강 |
| 6 | — | **균등 강화 모드**: 목적함수를 "콤보템 강화 총합 최대" ↔ "전체 강화 분산 최소"로 전환 |

## 3. 기능 ② 위키 빌드 브라우저 (M2)

### 데이터 (확인 완료)
- `GET https://www.sephiria.wiki/api/builds?page&limit&like&isLatestVersion&weapon&isWriter` → JSON.
- 빌드 필드: `title`, `description`(HTML), `costume/weapon/miracle`(슬러그), `combo[]`, `fruit_skewer[]`, `ability{7종 재능}`, `content[]`(섹션: label/description/items[슬러그]), `postLike`, `version`, `writer`, 날짜.
- **그리드 배치 정보는 없음** → 아이템 리스트 중심 UI (결정사항과 일치).

### 슬러그 → 아이콘/한글명 매핑
- 위키 아티팩트 페이지가 `<img alt="한글명" src="img.sephiria.wiki/artifacts/{슬러그}.png">` 구조 → 1회 스크레이프로 `슬러그→한글명` 테이블 생성, 한글명으로 우리 `assets/database.json`과 매칭해 로컬 아이콘 사용.
- 매칭 실패 시 위키 CDN 이미지 직접 표시로 폴백. 무기/기적/코스튬/콤보 슬러그도 동일 방식.

### UX
- `Ctrl+B` → 우측 패널. 리스트 뷰: 검색 + 필터(무기, 인기/최신순, 최신버전만) + 빌드 카드(제목·작성자·무기·기적·♥·버전).
- 카드 클릭 → 상세 뷰: 코스튬/무기/기적 칩, 콤보 뱃지, 재능 7종, 과일꼬치, 설명(HTML sanitize 후 렌더), 아티팩트 섹션들(라벨+아이콘열+설명).
- 응답은 로컬 캐시 (오프라인/위키 다운 시 마지막 캐시 표시). 요청 빈도 제한으로 위키 서버 부하 최소화.

## 4. 기능 ③ 팀원 패널 (M3, 후순위)

- 게임이 팀원 인벤토리를 클라이언트에 동기화(인게임 열람 가능 — 사용자 확인) → 플러그인이 팀원 `GridInventory`를 읽어 WS로 전송. **팀원 플러그인 설치 불필요** 가정.
- `F1` → 좌하단 패널: 팀원 탭 전환, 무기 칩 + 콤보 뱃지 + 미니 그리드(아이콘+강화수).
- M3 착수 시 최우선 검증: 멀티 세션에서 팀원 인벤 데이터가 실제로 로컬에서 읽히는지 (호스트/클라 각각).

## 5. 마일스톤

| 단계 | 내용 | 완료 기준 |
|------|------|-----------|
| M0 | 전체 레이아웃 시안 승인 | ← **현재. overlay-mockup.html 승인 대기** |
| M1 | 최적 배치 (엔진 개선 + 패널) | 실게임에서 계산→미니그리드 표시→수동 배치 재현 가능. 제약(회전불가/배치불가/발동조건) 위반 0건 |
| M2 | 위키 빌드 브라우저 | 실서비스 API로 목록/상세 표시, 슬러그 매핑 정상, 오프라인 캐시 동작 |
| M3 | 팀원 패널 | 멀티 세션에서 팀원 2인 이상 빌드 표시 |

각 마일스톤 착수 전, 해당 기능의 상세 시안(상태·엣지케이스 포함)을 갱신해 승인받는다.

## 6. 리스크 / 미해결

1. **석판 실제 데이터 추출**: 석판별 보너스 패턴·회전 가능 여부·배치 제약을 게임 어셈블리에서 찾아야 함 (M1 첫 조사 태스크).
2. **균등 강화 목적함수 정의**: "균등"의 수학적 정의(최소 강화수 최대화 vs 분산 최소화)는 M1 구현 중 실측으로 제안 후 확정.
3. **위키 API 비공식**: 스키마 변경/차단 가능성 → 캐시 + 요청 최소화, 파싱 실패 시 안내 표시.
4. **Borderless 확인**: 게임 설정에서 테두리 없는 창 지원 확인 필요 (미지원 시 창모드로 대체, 최악의 경우 IMGUI 플랜 B).
5. **F1 충돌**: 게임이 F1을 쓰는지 확인 (충돌 시 단축키 설정 기능으로 해결).
